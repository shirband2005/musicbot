# طرح سیستم خرید اشتراک ربات موزیک (روی کاغذ)

> وضعیت: طراحی روی کاغذ — منتظر تحقیق بله‌پی برای نهایی‌کردن آداپتور پرداخت ایرانی.

**هدف:** کاربرها در PV ربات اشتراک ربات را برای گروه خودشان بخرند؛ گروه پس از پرداخت فعال شود و با انقضا خاموش شود.

**تصمیم‌های کاربر (ثبت‌شده):**
- روش پرداخت (نهایی): **Telegram Stars + کارت‌به‌کارت (تأیید دستی) + کریپتو (USDT/TRON)**
- بله‌پی **حذف شد**: تحقیق نشان داد بله‌پی برای کاربر تلگرام مستقیماً کار نمی‌کند
  (پرداخت مستنددار بله نیاز دارد کاربر داخل اپ بله با یک ربات بله باشد؛ درگاه
  وب PayWeb API عمومی ندارد و نیاز به شناسه کسب‌وکار ایرانی + IP ایران دارد).
  اگر بعداً لازم شد → پروژه‌ی جدا: یک ربات بله‌ی موازی با python-bale-bot.
- پلن‌ها: زمان + امکانات ترکیبی
- انقضا: گروه خاموش + پیام تمدید در گروه و به خریدار
- مدیریت مالک: پنل مدیریت اشتراک‌ها (لیست/تمدید/لغو)
- احتمال اتصال به مینی‌اپ

**حقایق تأییدشده‌ی Telegram Stars (از تحقیق):**
- یک‌باره: `createInvoiceLink`/`sendInvoice` با `currency="XTR"`, `provider_token=""`,
  `prices=[LabeledPrice(label, amount)]` (amount = تعداد Stars). بدون provider token.
- اشتراک تکرارشونده: `createInvoiceLink` با `currency="XTR"` + `subscription_period=2592000`
  (۳۰ روز، تنها مقدار مجاز) + یک قیمت به‌ازای هر دوره. تلگرام خودش تمدید/لغو می‌کند.
- جریان: `pre_checkout_query` → `answerPreCheckoutQuery(ok=True)` → `successful_payment`
  (شامل `telegram_payment_charge_id` برای refund با `refundStarPayment`).

## ۱. مدل پلن‌ها (زمان + امکانات ترکیبی)

هر پلن = ترکیب یک **تیر امکاناتی** و یک **مدت**:

**تیرهای امکاناتی:**
| تیر | امکانات |
|---|---|
| پایه (basic) | پخش صوت، صف، یوتیوب+ساوندکلاد، پنل، حالت‌های پخش |
| حرفه‌ای (pro) | همه‌ی پایه + استریم ویدیو/فیلم حجیم + پخش رندوم از آرشیو + کیفیت بالاتر |

**مدت‌ها:** ۱ ماهه / ۳ ماهه / ۶ ماهه / دائمی

قیمت‌ها در یک جدول پیکربندی (قابل‌ویرایش توسط مالک) نگه داشته می‌شوند — نه هاردکد.

## ۲. دیتابیس (جداول جدید)

```sql
-- اشتراک هر گروه
CREATE TABLE subscriptions (
    chat_id     INTEGER PRIMARY KEY,   -- گروه
    tier        TEXT DEFAULT 'basic',  -- basic | pro
    expires_at  REAL,                  -- 0 = دائمی، وگرنه timestamp
    buyer_id    INTEGER,               -- کاربری که خرید
    started_at  REAL,
    last_notified REAL DEFAULT 0       -- برای پیام تمدید (ضد اسپم)
);

-- سفارش‌های پرداخت (همه‌ی روش‌ها)
CREATE TABLE orders (
    id          TEXT PRIMARY KEY,      -- شناسه یکتا (uuid)
    buyer_id    INTEGER,
    chat_id     INTEGER,               -- گروه هدف
    tier        TEXT,
    months      INTEGER,               -- 0 = دائمی
    amount      INTEGER,               -- مبلغ (تومان یا Stars)
    method      TEXT,                  -- stars | card | crypto | bale
    status      TEXT DEFAULT 'pending',-- pending | paid | rejected | expired
    ref         TEXT DEFAULT '',       -- شناسه تراکنش/رسید
    created_at  REAL,
    paid_at     REAL DEFAULT 0
);

-- جدول قیمت‌ها (قابل ویرایش مالک)
CREATE TABLE plan_prices (
    key    TEXT PRIMARY KEY,  -- مثل 'pro_3' (تیر_ماه)
    stars  INTEGER,           -- قیمت به Telegram Stars
    toman  INTEGER            -- قیمت به تومان (کارت/کریپتو/بله)
);
```

## ۳. جریان خرید (در PV ربات)

```
کاربر /start در PV → دکمه «خرید اشتراک»
   ↓
انتخاب گروه (ربات لیست گروه‌هایی که کاربر در آنها ادمین است + خودِ ربات عضو است را نشان می‌دهد)
   ↓
انتخاب تیر (پایه/حرفه‌ای)
   ↓
انتخاب مدت (۱/۳/۶/دائمی) → نمایش قیمت
   ↓
انتخاب روش پرداخت:
   [⭐ Stars] [💳 کارت‌به‌کارت] [🪙 کریپتو] [🌸 بله‌پی]
   ↓
یک order با status=pending ساخته می‌شود، سپس مسیر روش انتخابی
```

### آداپتور Stars (مطمئن‌ترین، API رسمی)
- `sendInvoice` با `currency="XTR"` و `provider_token=""` (Stars نیازی به provider ندارد)
- کاربر پرداخت می‌کند → `pre_checkout_query` تأیید → `successful_payment`
- order → paid → فعال‌سازی گروه
- کاملاً خودکار و آنی. **فاز ۱.**

### آداپتور کارت‌به‌کارت (تأیید دستی)
- شماره کارت + مبلغ به کاربر نشان داده می‌شود
- کاربر رسید (عکس) را به ربات می‌فرستد → به کانال لاگ/مالک فوروارد می‌شود
- مالک با دکمه [تأیید]/[رد] → order paid/rejected
- **فاز ۲.**

### آداپتور کریپتو (USDT/TRON)
- آدرس کیف پول + مبلغ (تبدیل تومان→USDT با نرخ) نشان داده می‌شود
- بررسی تراکنش: TronScan/TronGrid API (چک واریز به آدرس با مبلغ مطابق)
- یا مثل کارت، تأیید دستی با هش تراکنش
- **فاز ۳** (بعد از روشن‌شدن جزئیات).

### آداپتور بله‌پی (منتظر تحقیق)
- **نامشخص تا تحقیق:** درگاه وب redirect یا API بله؟ callback؟ نیاز به شناسه کسب‌وکار ایرانی؟
- به‌احتمال زیاد: ساخت لینک پرداخت → کاربر پرداخت → callback به یک وب‌سرور کوچک (aiohttp که الان داریم) → verify → order paid
- **فاز ۴** (پس از تحقیق).

## ۴. فعال‌سازی و انقضا

- **فعال‌سازی:** order paid → `subscriptions` آپدیت (tier + expires_at = now + months) → `group_config.set_enabled(chat_id, True)` + تنظیم تیر
- **گارد پخش:** `_gate` علاوه بر enabled، اشتراک فعال را هم چک کند؛ اگر منقضی → پیام تمدید
- **کنترل امکانات pro:** استریم ویدیو/فیلم حجیم و رندوم فقط اگر tier=pro
- **زمان‌بند انقضا:** یک لوپ (مثل nightly_backup) هر ساعت چک کند؛ اشتراک‌های منقضی:
  - `set_enabled(chat_id, False)`
  - پیام تمدید در گروه + به خریدار (buyer_id)
  - `last_notified` تنظیم شود تا اسپم نشود

## ۵. پنل مدیریت مالک

دستور «مدیریت اشتراک‌ها» (فقط مالک) در PV:
- لیست اشتراک‌های فعال: گروه، تیر، انقضا، خریدار
- روی هرکدام: [تمدید +۱ماه] [تمدید +۳ماه] [لغو] [تغییر تیر]
- فعال‌سازی دستی رایگان (هدیه)
- لیست سفارش‌های pending (کارت‌به‌کارت منتظر تأیید) + [تأیید]/[رد]

### زیربخش «تنظیمات پرداخت» (همه قابل‌ویرایش از پنل، نه هاردکد)
همه در جدول `pay_settings` (key/value) ذخیره می‌شوند و مالک از داخل ربات ویرایش می‌کند:
- **قیمت هر پلن**: برای هر کلید `<tier>_<months>` دو مقدار: Stars و تومان
  (مثلاً `basic_1`, `pro_3`, `pro_perm`) — با دکمه‌های [ویرایش قیمت]
- **شماره کارت** کارت‌به‌کارت + **نام صاحب کارت**
- **آدرس کیف‌پول کریپتو** (TRON/USDT) + شبکه
- **نرخ تبدیل تومان→USDT** (یا منبع نرخ خودکار)
- روش‌های فعال/غیرفعال (می‌شود مثلاً کریپتو را موقتاً خاموش کرد)

مکانیزم ویرایش: مالک روی دکمه می‌زند → ربات می‌پرسد «مقدار جدید را بفرست» →
مالک عدد/متن می‌فرستد (reply) → ذخیره در `pay_settings`. ساده و بدون نیاز به env.

```sql
CREATE TABLE pay_settings (
    key   TEXT PRIMARY KEY,   -- card_number | card_holder | crypto_addr | usdt_rate | method_crypto_on ...
    value TEXT
);
```

## ۶. مینی‌اپ (اختیاری، فاز آخر)
- یک Mini App (WebApp) که پلن‌ها و گروه‌ها را زیبا نشان دهد
- از همان orders/subscriptions backend استفاده کند
- initData را با BOT_TOKEN اعتبارسنجی کند (امنیت)
- به‌ویژه برای بله‌پی/کریپتو که UI بهتری لازم دارند مفید است

## ریسک‌ها و سؤالات باز
- بله‌پی: آیا از ربات تلگرام (نه بله) قابل استفاده است؟ نیاز به شناسه کسب‌وکار؟ (منتظر تحقیق)
- کریپتو: نرخ تبدیل تومان→USDT از کجا؟ (API نرخ لحظه‌ای لازم)
- Stars: نرخ تبدیل Stars→ارزش واقعی و برداشت (Telegram کارمزد دارد)
- «انتخاب گروه»: ربات باید بفهمد کاربر در کدام گروه‌ها ادمین است — نیاز به پیمایش گروه‌های مشترک
- امنیت: order id باید غیرقابل‌حدس باشد؛ verify پرداخت حتماً سمت سرور
